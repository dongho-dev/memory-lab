## 2026-11-07 · 프로젝트 시작

### 목표
- [소유자] 목적은 **더 좋은 메모리 시스템**을 만드는 것. 무관한 대화에 기억이 끼어드는 문제는 그중 작은 부분이다.
- [소유자] 잘 만들면 실제 에이전트에 붙여 쓴다.
- [소유자] 가장 작은 것부터 시작한다.

### 배경
- [관찰] 계층형 개인 메모리를 직접 운영하면 흔히 이런 문제가 생긴다.
  - 항상 주입되는 층이 비면, 새 대화마다 사람이 직접 "불러와"로 시동을 걸어야 한다.
  - 오프라인 정리(드리밍)가 없으면 쓰기 부담이 전부 사람에게 간다.
  - 트리가 깊으면 필요한 내용에 닿기까지 읽기 왕복이 많다.
  - 항상 켜진 메모리는 관련 없는 대화에도 끼어든다.

### 방법
- [합의] **가장 단순한 메모리(원문 검색)를 먼저 만들고, 이걸 이기는 층만 남긴다.** 정답률이 오르거나 토큰이 줄어야 남긴다.
  - 근거 [관찰]: CL-Bench에서 단순 컨텍스트 학습이 메모리 전용 시스템을 이김. Anthropic 글에서도 위키 단독(48%)이 검색 단독(53%)보다 낮음.
- [합의] 평가는 LongMemEval 서브셋으로 시작한다. 정답률과 질문당 토큰을 본다.
- [제안] 평가는 공개 벤치마크와 자체 제작을 섞는다. 도움·낡음은 LongMemEval, 침투는 OP-Bench/PersistBench류, 출처 혼동은 직접 만든다 (2026-11 조사 기준 전용 공개 벤치마크를 찾지 못함).
- [제안] 실사용 트랙을 따로 본다: "이번 주에 실제로 이걸 썼나". 메모리가 멈추는 이유는 정확도보다 시동 비용인 경우가 많다.

### 설계 아이디어 (아직 제안 단계)
- [소유자] **출처 태그**: 기억 항목마다 직접 발언 / 확정 / 검토안 / AI 해석을 구분한다. 이 저장소에 적용하는 방법은 [제안].
- [제안] 드리밍 결과는 diff로 남기고 사람이 승인한다. 특히 'AI 해석 → 확정' 승격은 반드시 승인.
- [제안] 게이트: 턴마다 "기억 안 씀 / 조용히 반영 / 명시적 언급"을 정한다. 임베딩 유사도가 아니라 추론으로 (RPEval: 의미 유사도로는 무관한 기억을 거의 못 거른다).
- [제안] 메모리의 순가치 = 관련 질문에서의 이득 − 무관 질문에서의 손해. CL-Bench의 gain을 둘로 나눠 잰다.
- [제안] 전달은 MCP 서버(remember / recall / dream).
- [제안] 실전 테스트베드는 객관적 피드백(리뷰어 PASS/FAIL, CI)이 있는 에이전트 파이프라인. 효과를 숫자로 잴 수 있다.

### 열린 질문
- 드리밍 주기와 망각 정책은 무엇을 기준으로 정하나 (접근 빈도? 정보 성격?)
- 자체 평가셋의 출처 혼동 문항은 어떻게 만들까?

## 2026-11-08 · 실행 방식

- [소유자] 모델 호출은 API 종량제가 아니라 **Claude 구독**으로 돌린다.
  - [관찰] 처음 하네스는 Anthropic API로 짜여 있었다. 소유자가 정한 게 아니라 Claude가 처음 만들 때 고른 것.
  - [합의] 로컬 Claude Code CLI를 백엔드로 붙이고 기본값으로 한다. API는 `--backend api`로 남긴다.
- [소유자] 가장 작고 가벼운 것부터 한다. 질문당 약 16.5만 토큰을 넣는 `full_context`(_s 전체 이력)로 시작하지 않는다.
  - [합의] 기준선 기본 실행은 no_memory · raw_search_k10 · oracle_full. `full_context`는 상한 참고용으로 `FULL=1`일 때만 돌린다.
- [소유자] 답변 모델은 Haiku / Sonnet / Opus로 나눠 각각 시험한다. effort도 변수로 본다.
  - [제안] 같은 메모리 층이라도 모델 세대에 따라 이득이 다를 수 있다(CL-Bench: 고정 규칙이 강한 모델에는 손해, 약한 모델에는 이득). 그래서 층마다 모델별 결과를 나란히 본다.
- [소유자] 메모리도 실행 방식도 작은 것부터 기록하며 천천히 살을 붙인다. 계층형 메모리를 한 번에 붙이는 건 나중에.
  - [합의] 실행 방식: 켜 둔 `claude` 프로세스에 `/clear`를 보내 문항마다 새 대화로 쓴다(`claude-code-session`, 기본값).
  - [제안] 기본 검색(raw_search_k10)에 붙일 순서: 검색 개수 → 자르는 단위(라운드/세션) → 날짜·출처 꼬리표 → 질의 확장 → … → 계층.
- [소유자] 저장소는 MIT로 공개한다. 개인 대화 기록은 저장소에 올리지 않는다.
